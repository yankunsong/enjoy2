# 用固定的本地假用户绕过账号，而不是拆除用户概念

Local Web Enjoy 不使用 Hosted Enjoy 账号，但 Desktop Enjoy 的 Library 数据库路径由账号 id 推导，且页面门禁依赖"已有用户"这个布尔条件。我们的做法是在启动时播种一个**固定的 8 位数字**本地用户 id，而不是把用户概念从代码里拆掉。

选 8 位数字不是随意的：既有的会话目录扫描按这个形状过滤，其他形状的 id 会导致本地档案不被识别。该 id 必须在数据库连接之前写入，否则路径推导不出来。

## Considered Options

**拆除用户概念**（改路径推导、改门禁定义、改所有以用户 id 为盐的 UUID 生成）在语义上更干净，但改动散落数十处。数据库 schema 中没有任何指向用户的外键，关联全部关闭了约束，用户 id 实际上只是路径前缀和 UUID 的盐——为此付出几十处改动收益为零。

## Consequences

这个 id 被烙进了两个地方：**Recording 的确定性 UUID**，以及 **Library 的目录名**。

因此它不是一个可以随手修改的常量。改动它会让已有的 Recording、Assessment 和媒体文件全部成为孤儿——数据仍在磁盘上，但新的路径和 UUID 找不到它们。若将来确实需要更换，必须同时迁移目录与重算 UUID。
